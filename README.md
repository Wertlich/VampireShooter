# Vampire Shooter

3D шутер от первого лица в духе vampire-survivors: ночная арена, орды нежити,
прокачка оружия. Проект на **Godot 4.7** (Forward+).

Рабочая папка устроена так: движок лежит отдельно, а сам проект — в этой папке.

```
D:\games godom\                   этот проект (открывать project.godot отсюда)
D:\GodotMCP\Godot\
  Godot_v4.7.2-stable_win64.exe         движок Godot 4.7
```

## Шаг 12 — сборка exe (готово)

Шаблоны экспорта Godot 4.7.2 лежат в `%APPDATA%\Godot\export_templates\4.7.2.stable\`,
пресет — `export_presets.cfg` («Windows Desktop», x86_64, pck внутри exe).

```
godot --headless --path "D:\games godom" --export-release "Windows Desktop" "D:\games godom\build\VampireShooter.exe"
```

Что получается в `build\`:

```
VampireShooter.exe          229 МБ, pck внутри
steam_appid.txt             480 (Spacewar) — для проверки лобби
addons\godotsteam\win64\    libgodotsteam.windows.template_release.x86_64.dll + steam_api64.dll
steam_api64.dll             дубль рядом с exe (его ищет сама steam_api)
VampireShooter_win64.zip    готовая папка для друга (92 МБ)
```

Нюанс: экспортёр кладёт библиотеки GDExtension в корень сборки, а `.gdextension`
ищет их по `res://addons/godotsteam/win64/...` — поэтому после экспорта DLL нужно
вернуть в `build\addons\godotsteam\win64\`, иначе игра стартует без Steam
(«Can't open dynamic library … Error 126»).

## Шаг 11 — интерполяция врагов и Steam (готово частично)

**Интерполяция.** Снапшоты врагов приходят 10 Гц, но «куклы» больше не
телепортируются: `NetworkGame._smooth_enemies()` тянет их к последней присланной
позиции (и повороту) с весом `delta * 14`, а при разрыве больше 6 м — мгновенно
догоняет (спавн). Для игроков то же самое уже было: `Player._process()`
интерполирует присланный `net_state`. На хосте добавлена проверка: телепорт
дальше 15 м за один снапшот отбрасывается.

**Steam.** Скачан и подключён **GodotSteam GDExtension 4.23.2** (Steamworks SDK
1.65, `compatibility_minimum = 4.4`) — работает на нашем Godot 4.7.2 без сборки
движка.

Что лежит в проекте:

```
addons/godotsteam/godotsteam.gdextension      конфиг расширения (только Windows x86_64)
addons/godotsteam/win64/                       libgodotsteam + steam_api64.dll
steam_appid.txt                                480 — тестовое приложение Spacewar
scripts/net/steam_bridge.gd                    init, лобби, приглашения
```

Возможности, которые **уже проверены на этой машине** (Steam запущен):

```
persona: Wert909
steam id: 76561198855407717
lobby: 109775241833505732 owner=true
lobby data addr: 127.0.0.1:27015
lobby members: 1
```

То есть инициализация, создание лобби, запись/чтение данных лобби и выход
работают. В меню «Онлайн» появился блок **STEAM · <ник>** с кнопками
«Создать лобби Steam», «Войти по ID», «Пригласить друга» (оверлей Shift+Tab).
Хост пишет в данные лобби свой `ip:порт`, гость читает и подключается по ENet,
так что IP руками вводить не нужно.

Важные ограничения:

- лобби сами по себе **не убирают необходимость проброса портов**: транспорт
  остаётся ENet. Для игры через интернет без проброса нужен Steam Datagram
  Relay (`SteamNetworkingSockets`) — это отдельный `MultiplayerPeerExtension`
  поверх `createListenSocketP2P`/`connectP2P`; в GodotSteam такие методы есть
  (`createListenSocketP2PFakeIP`, `connectP2P`, `receiveMessagesOnConnection`),
  но проверить это можно только на двух машинах с разными Steam-аккаунтами,
  поэтому в релиз я это не тащил;
- официальный `SteamMultiplayerPeer` требует **собственной сборки редактора**
  (у них релизы вида `win64-g451-...-mp.tar.xz`), с ванильным Godot 4.7 он не
  ставится;
- для настоящего релиза нужен свой App ID: положить `steam_appid.txt` со своим
  числом (в разработке 480 достаточно), а саму игру запускать из Steam.

## Шаг 10 — главное меню и онлайн-кооп (готово)

Точка входа теперь — **главное меню** (`scenes/main_menu.tscn`), а не сразу арена.

- **ИГРАТЬ** — одиночный забег (как раньше);
- **ОНЛАЙН** — страница с двумя кнопками: **Создать хост** и **Присоединиться**
  (поле IP, порт 27015, до 4 игроков);
- **НАСТРОЙКИ** — те же ползунки звука/видео/качества, что и в паузе
  (общий скрипт `scripts/ui/settings_panel.gd`);
- **ВЫХОД** — закрыть игру.

Сетевая модель — **host-authoritative**, то есть хост считает всё важное:

| Что | Кто считает |
| --- | --- |
| Волны, спавн, ИИ, урон | хост (`WaveManager`, `Enemy`) |
| Движение игрока | сам клиент, остальным шлём позицию 20 Гц |
| Попадания | хост: клиент просит «выстрелил отсюда туда», хост делает рейкаст |
| Здоровье игрока | хост считает, владельцу приходит `net_health` |
| Враги у клиентов | «куклы»: позиция/поворот/hp из снапшотов хоста 10 Гц |

Ключевые места:

- `scripts/net/net.gd` — роль (OFFLINE/HOST/CLIENT), ENet-пир, поиск локального
  игрока. Сделано на **статических** полях, а не автозагрузкой: headless-инструменты
  запускаются через `--script`, где автозагрузок нет.
- `scripts/net/network_game.gd` — спавн игроков на каждого пира, приветствие
  `net_hello`, снапшоты врагов, разрешение выстрелов.
- `scripts/player/player.gd` — `configure(peer_id)`, `is_local_player()`; у чужого
  игрока камера и view-model выключаются, вместо них капсула-заглушка и
  интерполяция присланной позиции.
- `scripts/enemies/enemy.gd` — `net_puppet` (без ИИ), `net_apply_health()`, выбор
  ближайшего живого игрока в цель.
- `scripts/world/wave_manager.gd` — волны крутит только хост; в снапшот попадает
  `net_kind`, чтобы клиент знал, какого врага создавать.

Проверка кооперации без окон: `tools/online_probe.gd` запускается двумя
процессами (host и client) и печатает, сколько игроков и врагов видит каждая
сторона. Сейчас оба процесса показывают `players=2 net_players=2 enemies=5`.

Ограничения первой версии: нет предсказания движения (при пинге больше ~60 мс
управление ощущается с задержкой), чужие игроки — капсулы без оружия, враги у
клиентов двигаются шагами по 0.1 с (без сглаживания), читы работают только
локально и на хосте.

## Шаг 10 — кладбище вместо замка (готово)

`scenes/main.tscn` собирает карту из отдельных сцен: трава вместо пола,
полуразрушенный деревянный забор по периметру, две отдельные церкви из
`models/dom` (целая и разрушенная), около сотни надгробий из
`LowPolyCemeteryGravePack`, уличные лампы из `models/lamp` и подвесные
клетчатые лампы из `lamp for dom`.
Ночное небо с облаками, звёздами и луной сделано шейдером в
`assets/cemetery/shaders/night_sky.gdshader`; сцена пересобирается скриптом
`tools/build_cemetery.gd`, а Blender-ассеты — `tools/blender_cemetery.py`.

Церковь собрана из отдельных сцен, а не из одного меша:

- `Model` — визуальный GLB;
- `Collision` — `church_intact_collision.tscn` / `church_ruined_collision.tscn`,
  внутри каждый элемент отдельным `CollisionShape3D`: `Floor`, `BackWall`,
  `NorthWall`, `SouthWall`, `FrontNorth`, `FrontSouth`, `EntranceRamp`,
  `NaveWall`;
- `LadderAccess` — `church_ladder.tscn`, внутри отдельно `Climb` (`Area3D`)
  и `Landing` (`StaticBody3D`).

Любую стену, пол или площадку можно двигать и растягивать прямо в инспекторе.
Лестница: подойди и держи `W` (или `Space`) — вверх, `S` — вниз; у верхней
кромки игрок сам сходит на площадку. Скорость — в `Player > Ladders`.
`build_cemetery.gd` эти узлы не пересоздаёт.

Что уже работает:

- старт только с револьвером: двустволка лежит «запертой», пока её не выпадет
  карточка;
- с врагов падают светящиеся кристаллы опыта: покачиваются, притягиваются к
  игроку с 5.5 м и растворяются в полоске опыта; красные кристаллы слизи дают
  больше XP, а выпавшие в воздухе сначала падают на пол;
- опыт и уровни: 24 XP на первый уровень, дальше нужно на 35% больше; полоска
  снизу по центру и подпись «УР. N»;
- на каждом уровне игра встаёт на паузу и предлагает 3 случайные карточки:
  открыть новое оружие (пока оно заперто — карточка гарантированно в наборе)
  либо улучшить имеющееся (урон, темп, магазин, перезарядка, точность);
- выбор мышью или клавишами 1/2/3, применение сразу видно по числам на карточке;

- карта на 100×100 м: кладбище с травяным полом, полуразрушенным деревянным
  забором и воротами, двумя церквями из `models/dom` (целой и разрушенной),
  рядами надгробий, склепами, обелисками и сухими деревьями;
- ночное небо: процедурные облака, звёзды и луна в шейдере, холодный
  направленный свет луны, туман и тёплые лампы;
- 10 уличных фонарей вокруг церкви и дорожек и 5 подвесных клетчатых ламп
  внутри церквей — все с мерцанием;
- коллизия карты — пол, стены церквей, алтарная стена и забор, а также боксы
  для всех надгробий, памятников, деревьев, ламп и обломков (`PropCollision`);
  ворота остаются проходимыми;

- полноценный FPS-контроллер: ходьба, бег, прыжок, покачивание головы,
  инерция камеры, захват курсора (Esc — освободить/вернуть);
- два вида оружия как view-model в отдельном `SubViewport` (узкий FOV,
  собственная подсветка, не проваливаются в стены): револьвер из
  `models/revolver` и двустволка из `models/shotgun`;
- переключение 1 / 2 (и колесом мыши): оружие убирается вниз, меняется в нижней
  точке и возвращается; у каждого свой боезапас, который сохраняется;
- прицеливание на ПКМ: оружие встаёт по прицельной линии, FOV сужается (78 → 62),
  разброс падает в 2–3 раза, чувствительность мыши и скорость ходьбы ниже,
  покачивание оружия почти пропадает, прицел-перекрестие гаснет;
- распрыжка: пробел можно держать — на касании земли сразу идёт следующий хоп;
  каждый хоп в цепочке даёт +5% горизонтальной скорости (потолок 14 м/с),
  в воздухе работает strafe-ускорение, FOV растягивается от реальной скорости,
  камера заваливается в сторону движения, в HUD — спидометр и счётчик цепочки;
- стрельба hitscan с разбросом, уроном и проверкой столкновений;
- скелет из `models/skelet`: выбирается из земли, бежит к игроку (анимация Run),
  бьёт когтями (анимация Attack) на 12 урона раз в 1.3 с, получает урон от обоих
  стволов, краснеет при попадании, получает отброс и падает замертво
  с растворением;
- слабая точка — **голова**: попадание выше 1.45 м от ступней даёт ×2 урона
  (револьвер 55 → 110, то есть ваншот) и усиленный отброс; в HUD крестик-хитмаркер:
  белый по корпусу, оранжевый по голове;
- скелеты не слипаются: коллизия по маске 7 (бьются и друг о друга) плюс мягкое
  расталкивание, поэтому группа расходится вокруг игрока, а не стоит комом;

- **волны вместо ручного спавна**: на одну карту 10 волн, каждая следующая больше
  ровно на 5 врагов (5, 10, 15, 20, …, 50, а десятая — один босс); волна
  вливается порциями по ~20 тиков, чтобы кадр не проваливался; волна считается
  отбитой, когда арена пуста, а между волнами 10 секунд передышки;
- **состав волн взрослеет**: скелеты исчезают к 7-й волне, зомби — к 10-й, а их
  место занимают лучники и слизи; состав каждой волны задан таблицей `WAVE_MIX`,
  так что тяжесть растёт плавно, без скачков;
- всё это видно в HUD: по центру сверху «ВОЛНА 2/10» либо
  «ВОЛНА 1/10 ЗАЧИЩЕНА · СЛЕДУЮЩАЯ ЧЕРЕЗ 8», справа счётчик живых врагов;
- **смерть работает**: на нуле здоровья камера заваливается, игра встаёт на паузу
  и показывает «ВЫ ПОГИБЛИ» с волной, уровнем и числом убитых скелетов;
  R или ЛКМ — заново (сцена перезагружается, забег начинается с нуля);
- **карточка здоровья**: в наборе повышений есть «Здоровье +25%» — поднимает
  максимум HP и лечит до полного, рядом с улучшениями оружия;
- **чит на бессмертие и ваншот**: ↑ ↑ ↓ ↓ ← → ← → B A на стрелках (и буквы B, A).
  Включает сразу два эффекта — урон по игроку игнорируется, а любой выстрел из
  любого оружия убивает врага с первого попадания (урон умножается до 1e9).
  Повтор ввода выключает оба; в HUD слева сверху загорается
  «БЕССМЕРТИЕ + ВАНШОТ ВКЛ»;
- **клавиша `\` стягивает всех живых врагов к игроку**: они встают кольцом вокруг
  персонажа — удобно проверить оружие, толпу или экран смерти, не дожидаясь,
  пока волна дойдёт сама;
- АКМ из `models/akm`: вороненая сталь и дерево вместо белого пластика, см.
  «Текстуры АКМ» ниже;

- револьвер: 6 патронов, перезарядка ~2.1 с с вращением барабана, небольшая отдача;
- двустволка: 2 патрона, 9 дробин за выстрел, медленная (0.9 выстр./с),
  большая отдача и перезарядка-«переломка» ~2.6 с;
- **РПД**: 100 патронов, 10.5 выстр./с (самый быстрый после MP9), урон 30 —
  чуть больше АКМ, отдача мягкая, перезарядка 5 с; за тяжёлый ствол приходится
  платить мобильностью — ходьба и бег с ним в руках замедлены до **75%**;
- **Сайга-12К**: 8 патронов, 9 дробин, урон и разброс как у двустволки (16 и 6.5°),
  а темп как у СВД — 1.1 выстр./с;
- **MP9**: 15 выстр./с (самый быстрый ствол в игре), урон 48 — чуть меньше
  револьвера, магазин 30, перезарядка 1.9 с; есть **модификация «Двойные MP9»** —
  второй ПП в левую руку, магазин ×2 (60) и вспышки по очереди. Карточка
  модификации выпадает **гарантированно** на первом же повышении после того, как
  MP9 оказался в руках (а не теряется в общем пуле улучшений);
- отдача камеры и модели (чем тяжелее оружие, тем сильнее), толчок камеры назад,
  вспышка выстрела, искры и вспышка в точке попадания;
- процедурные звуки: выстрелы, холостые щёлканья, перезарядки (у каждого оружия свои);
- HUD: прицел, счётчик патронов, название оружия и его живые характеристики
  (урон, темп, магазин, перезарядка, разброс, а у РПД — ещё и штраф к ходу) —
  обновляются при апгрейдах и смене ствола; подсказки и спидометр.

## Золотые печати оружия

После **трёх обычных улучшений** (урон / темп / магазин / перезарядка / разброс)
в наборе повышений появляется **золотая печать**. У неё нет подписей — только
изображение ствола, которому она принадлежит. Клик по печати открывает отдельное
окно, где лежат **только печати этого оружия**; из них выбирается одна. После
этого ствол больше не получает печатей: одно золотое улучшение на оружие за
забег.

- **Револьвер — «Горящий крест»**: каждый хэдшот даёт +5% урона и +4% темпа
  (до 10 стаков). Над прицелом горит крест, который разгорается ярче с каждым
  стаком; гаснет через 3 с без хэдшота.
- **Револьвер — «Пороховая печать»**: убийство в голову вызывает взрыв на
  **1/3 базового урона** в радиусе 5 м.
- **Двустволка — «Кувалда»**: разброс +60%, но выстрел отбрасывает стрелка
  назад и подкидывает.
- **АКМ — «Кровавый ручей»**: 5% нанесённого урона возвращается здоровьем.
- **АКМ — «Перегрев»**: каждое убийство даёт +8% темпа и +6% скорости
  перезарядки на 3 с. С 6 стаков АКМ начинает жечь стрелка за каждый выстрел,
  а HUD показывает «ПЕРЕГРЕВ» и оранжевую пелену.
- **СВД — «Бронебойный»**: пуля проходит насквозь до 8 врагов.
- **СВД — «Азарт охотника»**: +8% темпа за хэдшот (до 10). Сбрасывается после
  3 с без хэдшота, промаха или перезарядки.
- **РПД — «Тяжёлый калибр»**: +20% урона, но ход с пулемётом падает до 65%.
- **Сайга-12К — «Сдвоенный залп»**: темп как у АКМ, два быстрых выстрела за
  клик, каждая дробинка пробивает врагов насквозь.
- **MP9 — «Свинцовый рой»**: +25% темпа и +20% магазина.

Золотые печати живут в [unique_cards.gd](scripts/weapons/unique_cards.gd),
эффекты — в `weapon.gd`, а стиль, окно выбора и картинки — в `levelup_menu.gd`
и `assets/ui/seals/`.

## Границы арены и настройки

- **Невидимые стены**: [arena_bounds.gd](D:\games godom\scripts\world\arena_bounds.gd)
  строит четыре бокса 16 м высотой по краям карты (±48 м), слой `world`. Ворота и
  щели между башнями больше не выпускают никого наружу.
- **Страховка от вылета**: тот же узел раз в полсекунды проверяет всех из группы
  `enemies` — если врага отбросило за стену или он провалился ниже -8 м, его
  телепортирует в центр арены с разбросом ±2.5 м и обнулённой скоростью. Игрока
  при падении за карту возвращает на точку респавна (позиция на старте).
- **Настройки на Esc**: [pause_menu.gd](D:\games godom\scripts\ui\pause_menu.gd) —
  пауза, кнопки «Продолжить» и «Выход» (выход из игры; настройки к тому моменту
  уже сохранены) и три блока:
  - звук: общая громкость (шина Master);
  - видео: разрешение (1280×720 … 2560×1440), полный экран, вертикальная
    синхронизация;
  - качество: **низкое / среднее / высокое** — MSAA (выкл / 2× / 4×), масштаб
    рендера (0.75 / 1.0 / 1.0), SSAO, свечение и туман, дальность теней
    (60 / 120 / 170 м) и размер атласа теней.
- Всё применяется на лету и запоминается в `user://settings.cfg`
  ([settings.gd](D:\games godom\scripts\settings.gd)) — после перезапуска игра
  стартует с выбранными значениями.

## Враги

Все пятеро — одна сцена-мозг [enemy.gd](D:\games godom\scripts\enemies\enemy.gd) с
разными экспортами и моделью, поэтому вспышка от попадания, отброс, хедшоты,
гемы опыта и растворение при смерти работают одинаково.

| Враг | Модель | HP | Поведение |
| --- | --- | --- | --- |
| Скелет | `models/skelet/animated/skeleton.glb` | 120 | бежит вплотную, бьёт когтями |
| Зомби (враг v2) | `models/vrag v2/zombie_a…d.glb` — 4 варианта | 180 (×1.5) | медленнее скелета, но крепче; бьёт когтями |
| Слизь (враг v3) | `models/vrag v3/ghostbusters_slimer.glb` | 360 (×2 к зомби) | летает высоко и пикирует сверху вниз, крупная и быстрая |
| Лучник | `models/vrag skeleton archer/low_poly_skeleton_archer_animated.glb` | 180 (как зомби) | мельче остальных (~1.6 м), держит 9 м, отходит при 5.5 м, перед выстрелом ~1 с натягивает лук |
| Босс | `models/new boss/daemonium.glb` (≈6 м) | 2520 (×7 к слизи) | только на 10-й волне, один, бьёт на 32 и использует огненную стену и ряды рук |

- Лучник стреляет настоящими стрелами ([arrow.tscn](D:\games godom\scenes\fx\arrow.tscn)):
  снаряд летит 18 м/с, проходит только сквозь других врагов, а стены и игрока
  останавливают его. Перед выстрелом лучник ~1 секунду натягивает лук
  (`attack_hit_delay`) — выстрел видно заранее и от него можно уйти. Если у
  лучника нет линии видимости, он не стреляет и подбирается ближе, а вплотную —
  отступает и смещается боком.
- Слизь летает по-настоящему: тело поднимается на `flight_altitude` (4.5 м) и
  плавно пикирует к игроку по мере сближения, вплоть до `flight_low_altitude`
  (1.5 м). Коллизия — сфера r=1.2 м прямо в центре летящей туши, поэтому
  попадания засчитываются по видимому слизню, а не по месту под ним.
- **Кристаллы слизи** — красные, tier 2: каждый даёт 16 XP вместо 8 и больше по
  размеру. Если враг погиб в воздухе, кристаллы сначала падают на пол под
  действием гравитации и только потом притягиваются к игроку.
- **Босс Daemonium** — новый многорукий демон из `models/new boss`, ~6 м ростом.
  Раз в 8.5 с чередует две площадные атаки:
  - **Стена огня**: горящее кольцо расходится от босса на **20 м** за 1.15 с,
    наносит 30 урона при прохождении через игрока и подсвечивает арену.
  - **Руки из-под земли**: вперёд на **15 м** поднимаются **3 ряда по 15 рук**
    (45 штук) из `models/arm`, со смещениями и пересечением зон. Каждая рука
    наносит 14 урона, поднимается с задержкой и уходит обратно в пол.
  - После смерти босс роняет **12 золотых кристаллов**: каждый даёт **48 XP**
    (втрое больше красного) и втрое больше красного по размеру (scale 3.6
    против 1.2), золотого цвета.
- Состав волн — таблица `WAVE_MIX` в [wave_manager.gd](D:\games godom\scripts\world\wave_manager.gd):
  1–2 только скелеты, с 3-й подмешиваются зомби, с 4-й лучники, с 6-й слизь;
  скелеты пропадают к 7-й волне, зомби — к 10-й, то есть каждая волна не только
  больше, но и злее; десятая волна — всегда один босс и ничего больше.
- **Рандомайзер зомби**: в сцене `enemy_zombie.tscn` лежит массив `variants` из
  четырёх персонажей пачки — при спавне берётся случайный. Сверху каждый зомби
  получает свой оттенок текстур (`random_tint`, сила `tint_strength`), случайную
  яркость и масштаб 0.94–1.06, поэтому толпа не выглядит клонами.
- Зомби вырезаны из пачки `polyart-zombies` (там десять персонажей на подставке в
  одном GLB) утилитой [extract_glb_part.py](D:\games godom\tools\extract_glb_part.py):
  она оставляет один узел с его кожей и дорожками анимации, пересчитывая индексы, и
  заново собирает бинарник только из нужных байтов (иначе каждый вариант весил бы
  все 7 МБ пачки).
- Тёмные модели (зомби) подсвечиваются множителем `albedo_boost`, а не
  эмиссией: эмиссия вымывала текстуру в белое пятно.
- **Текстуры оружия**: у РПД текстуры (дерево + металл) приходят в GLB, поэтому
  сцена включает `keep_materials` и ничего не перекрашивает. У Сайги и MP9
  текстур в файлах нет вообще — им назначен трипланарный
  [gun_polymer.tres](D:\games godom\assets\materials\gun_polymer.tres) (тёмный
  полимер со царапинами, за основу взяты карты от вороненой стали АКМ).

## Текстуры АКМ

Исходный `models/akm/raw/AKM.fbx` пришёл без текстур и без UV: в GLB лежат 12
плоских серых материалов с `baseColor 0.8`, из-за чего автомат выглядел белым
пластиком. Поэтому текстуры сделаны процедурно, а развёртки нет — материалы
сэмплируют их **трипланарно** (`uv1_triplanar`), и волокна дерева идут вдоль U,
то есть вдоль ствола на боковых проекциях приклада и цевья.

- [make_akm_textures.py](tools/make_akm_textures.py) пишет шесть карт:
  `assets/textures/akm_wood_{albedo,roughness,normal}.png` и
  `akm_metal_{albedo,roughness,normal}.png`;
- [akm_wood.tres](assets/materials/akm_wood.tres) — лакированная берёза
  (metallic 0, roughness по карте, лёгкая эмиссия 0.10, чтобы оружие читалось
  в тёмном зале);
- [akm_metal.tres](assets/materials/akm_metal.tres) — вороненая сталь
  (metallic 0.6, roughness по карте, эмиссия 0.16);
- сцена [weapon_akm.tscn](scenes/weapon_akm.tscn) раздаёт их через
  `surface_materials`: слоты 0–9 — сталь (ресивер, крышка ствольной коробки,
  ствол, газовая трубка, магазин, прицельные), слоты 10 и 11 — дерево
  (пистолетная рукоять, приклад и цевьё).

Какая поверхность какой детали соответствует, видно по
[preview_surfaces.gd](tools/preview_surfaces.gd): он рендерит модель по одному
материалу за кадр. Проверить вид оружия в настоящем view-model (и позу
прицеливания) — [preview_akm_ingame.gd](tools/preview_akm_ingame.gd).

## Анимации скелета (Blender → GLB)

Исходник — статический OBJ без рига, поэтому арматура и анимации собраны скриптами
Blender 5.2 (через `bpy`, headless):

1. [blender_analyze.py](tools/blender_analyze.py) — обмер меша: высоты суставов и
   положение конечностей по срезам.
2. [blender_rig.py](tools/blender_rig.py) — арматура (root, hips, spine, chest, neck,
   head, руки, ноги) и жёсткий скининг по ближайшей кости с подмешиванием у суставов;
   сохраняет `.blend`.
3. [blender_animate.py](tools/blender_animate.py) — экшены **Run** (16 кадров) и
   **Attack** (24 кадра), экспорт `skeleton.glb` вместе с анимациями.

Пересборка:

```powershell
$blender = "C:\Program Files (x86)\Steam\steamapps\common\Blender\blender.exe"
& $blender --background --factory-startup --python tools\blender_rig.py -- `
    models\skelet\source\skeleton_rigged.obj `
    models\skelet\animated\blend\skeleton_rig.blend screenshots\rig
& $blender --background --factory-startup --python tools\blender_animate.py -- `
    models\skelet\animated\blend\skeleton_rig.blend `
    models\skelet\animated\skeleton.glb screenshots\rig
```

Godot крутит **Run** в цикле (темп зависит от реальной скорости) и проигрывает
**Attack** один раз, нанося урон на 0.45 с — в момент замаха. Папка
`models/skelet/animated/blend` помечена `.gdignore`: иначе Godot пытается
импортировать `.blend` и требует прописанный путь к Blender.

## Карта замка (Blender → GLB + JSON)

[blender_castle.py](tools/blender_castle.py) собирает карту целиком кодом: стены с
зубцами, башни, ворота, собор с колоннадой и арками, витражи, горгульи, надгробия,
свечи и жаровни. Геометрия склеивается по материалам (несколько мешей вместо сотен),
а рядом с GLB пишется `castle_data.json`:

- `collision` — 68 коробок (стены, башни, платформа, колонны, пьедесталы, ворота собора);
- `candles` и `braziers` — точки, где Godot создаёт источники света;
- `player_spawn`.

```powershell
$blender = "C:\Program Files (x86)\Steam\steamapps\common\Blender\blender.exe"
& $blender --background --factory-startup --python tools\blender_castle.py -- `
    models\castle\castle.glb models\castle\castle_data.json screenshots\castle
```

[castle.gd](scripts/world/castle.gd) на старте читает JSON, строит `StaticBody3D`
с коробками и зажигает 54 свечи + 4 жаровни с мерцанием. Обзорные кадры карты —
[preview_map.gd](tools/preview_map.gd).
